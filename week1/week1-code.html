📐 1 · Complexity Analysis

When you solve a problem, you need to answer two questions before writing a single line: How much time will this take? and How much memory will it use? Complexity notation gives us a language-independent way to answer both.

The Three Notations

Big O (O) — Upper bound. The worst case. "It will never take longer than this."
Big Omega (Ω) — Lower bound. The best case. "It can't be faster than this."
Big Theta (Θ) — Tight bound. When worst and best are the same order. Most useful in practice.

Rules for Simplifying Big O

Drop constants: O(2n) → O(n)
Drop lower-order terms: O(n² + n) → O(n²)
Different variables stay separate: O(a + b) is NOT simplified to O(n)
Multiplication for nested work: outer loop × inner work = O(n × m)

Space Complexity

Space complexity counts auxiliary memory your algorithm allocates (not the input itself). A recursive function with depth d uses O(d) call-stack space — always account for this.

Pythondef example_space(nums: list[int]) -> list[int]:
    # O(n) time, O(n) space — we allocate a new list of same size
    result = []
    for x in nums:
        result.append(x * 2)
    return result

def in_place_double(nums: list[int]) -> None:
    # O(n) time, O(1) space — mutates input, no extra allocation
    for i in range(len(nums)):
        nums[i] *= 2

🔍 2 · Binary Search

Binary search works on any monotonic (sorted or decision-able) space. Each step halves the search space → O(log n). The key insight is the invariant: the answer always lies within [lo, hi].

The Three Templates

Template 1 — Classic (exact match): while lo <= hi
Template 2 — Left boundary: while lo < hi, answer is lo
Template 3 — Right boundary: while lo < hi, answer is hi-1 
Pythondef binary_search(nums: list[int], target: int) -> int:
    """Returns index of target or -1. Time O(log n), Space O(1)."""
    lo, hi = 0, len(nums) - 1
    while lo <= hi:
        mid = lo + (hi - lo) // 2  # avoids integer overflow vs (lo+hi)//2
        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1

# ── Generalized: "find first index where condition is True" ──
def first_true(nums: list[int], target: int) -> int:
    """Returns leftmost position where nums[i] >= target."""
    lo, hi = 0, len(nums)
    while lo < hi:
        mid = (lo + hi) // 2
        if nums[mid] >= target:
            hi = mid
        else:
            lo = mid + 1
    return lo
⚠ Classic bug: Writing mid = (lo + hi) // 2 is fine in Python (arbitrary integers), but in other languages this can overflow for large arrays. Always use lo + (hi - lo) // 2 as a habit.

👉👈 3 · Two Pointers

Two pointers eliminates the need for nested loops when you need to find a pair (or range) in a sorted structure. Instead of O(n²), you scan once from both ends: O(n).

When to use it

✔ Array/string is sorted (or can be sorted cheaply)
✔ You need to find a pair/triplet that satisfies a sum or condition
✔ You need to compare characters from both ends (palindrome check) 
Pythondef two_sum_sorted(nums: list[int], target: int) -> tuple[int, int]:
    """Find indices of two numbers that add to target. O(n) time, O(1) space."""
    lo, hi = 0, len(nums) - 1
    while lo < hi:
        s = nums[lo] + nums[hi]
        if s == target:
            return (lo, hi)
        elif s < target:
            lo += 1   # need bigger sum
        else:
            hi -= 1   # need smaller sum
    return (-1, -1)

def is_palindrome(s: str) -> bool:
    """Two-pointer palindrome check. O(n) time, O(1) space."""
    lo, hi = 0, len(s) - 1
    while lo < hi:
        if s[lo] != s[hi]:
            return False
        lo += 1
        hi -= 1
    return True

🪟 4 · Sliding Window

Use a sliding window when you need to examine a contiguous subarray or substring of variable or fixed size. A window expands by moving the right pointer and contracts by moving the left pointer — each element is added and removed at most once, giving O(n).

Fixed-size vs. Variable-size windows

Fixed window: right − left + 1 == k always. Slide by one each step.
Variable window: expand right until constraint is violated, then shrink from left. 
Python# ── Fixed window: max sum of k consecutive elements ──
def max_sum_k(nums: list[int], k: int) -> int:
    """O(n) time, O(1) space."""
    window = sum(nums[:k])
    best = window
    for i in range(k, len(nums)):
        window += nums[i] - nums[i - k]   # slide: add right, drop left
        best = max(best, window)
    return best


# ── Variable window: longest substring without repeating chars ──
def length_of_longest_substring(s: str) -> int:
    """O(n) time, O(min(n, 26)) space."""
    seen = {}   # char → last seen index
    lo = best = 0
    for hi, ch in enumerate(s):
        if ch in seen and seen[ch] >= lo:
            lo = seen[ch] + 1   # shrink: jump lo past duplicate
        seen[ch] = hi
        best = max(best, hi - lo + 1)
    return best

Decision Framework: Which pattern do I use?

Sorted array + find pair/triplet? → Two Pointers
Contiguous subarray/substring + optimal length? → Sliding Window
Sorted array + find element / boundary? → Binary Search
Anything + brute-force nested loops? → First ask: can I binary search or use two pointers?
