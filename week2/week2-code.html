Recursion & Backtracking

Recursive thinking · Permutations · Subsets · Backtracking template

🎯 Learning Objectives

  • Model problems using recursive decomposition (base case + recursive case).
  • Analyze the time complexity of recursive algorithms using the call-tree method.
  • Generate all permutations of a string/array using recursion.
  • Generate all subsets (power set) of a set using recursion.
  • Apply the backtracking template: choose → explore → unchoose.
  • Identify when recursion is preferable and when it introduces unnecessary overhead.

🧠 1 · Recursive Thinking

Recursion is a function calling itself on a smaller version of the same problem. Every recursive solution needs exactly two parts:

Base case: The smallest problem that can be solved directly without recursion.
Recursive case: Reduce the current problem to a smaller version and call self.

A useful mental model: "Assume the recursive call works correctly, and just write what you need to do with its result." Trust the recursion.

Call Stack Visualization

Pythondef factorial(n: int) -> int:
    if n <= 1:          # base case
        return 1
    return n * factorial(n - 1)  # recursive case

# Time O(n), Space O(n) — n frames on the call stack

def sum_digits(n: int) -> int:
    """Sum of digits of a non-negative integer. e.g. 123 → 6"""
    if n < 10:
        return n
    return n % 10 + sum_digits(n // 10)

Analyzing Recursive Complexity

Method: Draw the call tree. Count nodes (total calls) for time complexity. Count the maximum stack depth for space complexity.

Pattern: If each call spawns b sub-calls and the depth is d, total calls ≈ bd.
Factorial: 1 sub-call, depth n → O(n) time, O(n) space.

🔄 2 · Generating Permutations

A permutation is an arrangement of all elements in a specific order. For n distinct elements there are n! permutations.

Strategy: fix one element at each position, recurse for the rest, then restore (backtrack).

Pythondef permutations(chars: list[str]) -> list[list[str]]:
    """Generate all permutations. Time O(n·n!), Space O(n·n!)."""
    results = []

    def backtrack(current: list[str], remaining: list[str]):
        if not remaining:          # base case: nothing left to pick
            results.append(list(current))
            return
        for i in range(len(remaining)):
            current.append(remaining[i])              # CHOOSE
            backtrack(current, remaining[:i] + remaining[i+1:])  # EXPLORE
            current.pop()                             # UNCHOOSE (backtrack)

    backtrack([], chars)
    return results

# Example: permutations(['A','B','C'])
# → [['A','B','C'],['A','C','B'],['B','A','C'],
#    ['B','C','A'],['C','A','B'],['C','B','A']]
⚠ Why O(n·n!)? There are n! permutations and each requires O(n) time to copy into results. The total calls in the tree is 1 + n + n(n-1) + … ≈ e·n! which is still O(n!).

📦 3 · Generating Subsets (Power Set)

The power set of n elements has 2ⁿ subsets (including empty set). For each element, we make a binary choice: include it or skip it.

Pythondef subsets(nums: list[int]) -> list[list[int]]:
    """Power set. Time O(n·2ⁿ), Space O(n·2ⁿ)."""
    results = []

    def backtrack(start: int, current: list[int]):
        results.append(list(current))  # every node is a valid subset
        for i in range(start, len(nums)):
            current.append(nums[i])    # CHOOSE
            backtrack(i + 1, current) # EXPLORE (only elements after i)
            current.pop()              # UNCHOOSE

    backtrack(0, [])
    return results

# subsets([1,2,3]) → [[], [1], [1,2], [1,2,3], [1,3], [2], [2,3], [3]]

🔙 4 · The Backtracking Template

Backtracking is a controlled brute-force: build a candidate solution incrementally and abandon a path early ("prune") when it can no longer lead to a valid solution.

Template (memorize this):
CHOOSE → make a decision, add to current state
EXPLORE → recurse into the next level
UNCHOOSE → undo the decision (restore state)

Application: Combinations of size k

Pythondef combinations(n: int, k: int) -> list[list[int]]:
    """All k-length combinations from 1..n. Time O(k·C(n,k))."""
    results = []

    def backtrack(start: int, current: list[int]):
        if len(current) == k:        # base case: found a complete combination
            results.append(list(current))
            return
        # pruning: no need to go past n-(k-len(current))+1
        limit = n - (k - len(current)) + 2
        for i in range(start, limit):
            current.append(i)          # CHOOSE
            backtrack(i + 1, current) # EXPLORE
            current.pop()              # UNCHOOSE

    backtrack(1, [])
    return results

# combinations(4, 2) → [[1,2],[1,3],[1,4],[2,3],[2,4],[3,4]]

Complexity summary

ProblemTimeSpace (output)Key insight
FactorialO(n)O(n)One path, no branching
PermutationsO(n·n!)O(n·n!)n choices at each of n levels
SubsetsO(n·2ⁿ)O(n·2ⁿ)2 choices (include/skip) at n levels
Combinations k of nO(k·C(n,k))O(k·C(n,k))Pruning reduces constant factor
💡 Interview tip: Always state the complexity in terms of output size for backtracking problems. The output itself is exponential — the best possible algorithm still has to write each result, so exponential output implies exponential time.
