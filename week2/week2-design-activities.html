⚡ Part A — Quiz

Question 1

A load balancer uses IP Hash to assign requests. What is the main benefit of this strategy?

  • It always sends requests to the fastest server
  • The same client always reaches the same server (session stickiness)
  • It evenly distributes load regardless of session
  • It works only at Layer 4
Session stickiness — if your app stores session state on the server (not in a shared DB/cache), the same client must always reach the same server. IP Hash guarantees this.
Question 2

A CDN edge node has no cached copy of an image. What happens next?

  • The request fails with a 404
  • The user is redirected to a different edge node
  • The edge node fetches from the origin server and caches the response
  • The user downloads directly from origin without CDN involvement
Cache miss in a pull CDN: the edge fetches from origin, stores it with the TTL defined in Cache-Control headers, then serves it to the user. Subsequent requests for the same file hit the edge (cache hit).
Question 3

Which caching strategy writes to BOTH the cache and the database at the same time?

  • Cache-aside
  • Write-through
  • Write-back
  • Read-through
Write-through — on every write, data is synchronized to both cache and DB simultaneously. Slower writes than write-back, but no risk of data loss and cache always consistent with DB.
Question 4

What is the primary role of an API Gateway in a microservices architecture?

  • Store session data for users
  • Cache database query results
  • Compress images before sending to clients
  • Single entry point that handles auth, routing, and rate limiting
The API gateway is the single entry point. It centralizes cross-cutting concerns — authentication, authorization, rate limiting, SSL termination, logging — so each microservice does not need to re-implement them.
Question 5

A Redis Sorted Set stores player scores. What is the time complexity of finding the rank of a player?

  • O(1)
  • O(log n)
  • O(n)
  • O(n log n)
O(log n) — Redis Sorted Sets use a skip list internally. ZRANK and ZSCORE operations are O(log n). This is why sorted sets are ideal for leaderboards.

🖊️ Part B — Architecture Workshop (In-class)

In groups of 2, draw the architecture for each scenario on the whiteboard. Label every component. Identify which building blocks from this week you are using and why.

Scenario 1 — E-commerce product page

A product detail page loads: product image (2MB), product description (from database), and real-time inventory count. 500K concurrent users during a flash sale.

Questions to answer: Where would you add a CDN? What would you cache in Redis and for how long? How many load balancers do you need? What is the cache invalidation strategy for inventory?

Scenario 2 — Authentication service

Every API call across 10 microservices requires verifying a JWT token. Currently each microservice calls the auth DB on every request → 10,000 DB calls/sec.

Questions to answer: Where does the API gateway fit? How can Redis reduce DB load? What cache TTL is appropriate for a JWT that expires in 1 hour?

🤝 Part D — Design Review Checklist

  • CDN placed in front of static assets (not dynamic API responses)?
  • Load balancer health check configured (not just assumed always-up)?
  • Cache strategy named (cache-aside, write-through, etc.) and justified?
  • TTL value specified for each cached item — not just "cache it"?
  • API Gateway identified as the single entry point for auth?
  • Single points of failure identified and mitigation proposed?
