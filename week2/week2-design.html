🌐 1 · DNS — Domain Name System

DNS is the internet's phonebook. When you type www.example.com, your browser does not know the IP address. DNS translates the human-readable domain name into the IP address of the server.

TTL (Time-To-Live): DNS records have a TTL value in seconds. Until TTL expires, the IP is cached locally and no new DNS query is made. Long TTL = fewer queries but slower propagation of IP changes. Short TTL = faster changes but more load on DNS servers.

🌍 2 · CDN — Content Delivery Network

A CDN is a geographically distributed network of edge servers that cache static content (images, JS, CSS, videos) close to users. Instead of all users hitting your origin server in one country, they hit the nearest CDN edge node.

CDN StrategyHow it worksBest for
Pull CDNEdge fetches from origin on first miss, caches for TTLStatic assets that change infrequently
Push CDNYou push content to CDN before users request itLarge files (videos) where you control upload timing

⚖️ 3 · Load Balancers

A load balancer distributes incoming traffic across multiple servers, preventing any single server from becoming a bottleneck.

Layer 4 vs. Layer 7

Layer 4 (Transport): Routes based on IP/TCP. Fast, lower overhead. Cannot inspect HTTP content.
Layer 7 (Application): Routes based on HTTP headers, URL path, cookies. Can implement content-based routing (e.g., /api/* → API servers, /static/* → CDN).

Load Balancing Algorithms

AlgorithmHow it worksBest for
Round RobinCycle through servers in orderServers with similar capacity
Weighted Round RobinServers get requests proportional to their weightHeterogeneous server fleet
Least ConnectionsSend to server with fewest active connectionsLong-lived connections (WebSocket)
IP HashHash client IP → always same serverSession stickiness (stateful apps)
Health checks: Load balancers periodically ping each server (e.g., GET /health → 200 OK). If a server fails, the LB stops sending traffic to it. This is how the system achieves high availability without human intervention.

🚪 4 · API Gateway & Proxies

API Gateway

An API gateway is the single entry point for all clients. It sits in front of your microservices and handles cross-cutting concerns.

What an API gateway does:
• Authentication & Authorization — verify JWT tokens before requests reach services
• Rate Limiting — throttle abusive clients
• Request Routing — forward to the correct microservice based on path
• Protocol Translation — e.g., REST → gRPC
• SSL Termination — handle HTTPS, pass HTTP internally

Forward vs. Reverse Proxy

TypeSits betweenProtectsExample
Forward ProxyClients → InternetClients (hides their identity)Corporate VPN, privacy proxy
Reverse ProxyInternet → ServersServers (hides their identity/IP)Nginx, Cloudflare, API Gateway

⚡ 5 · Caching with Redis

A cache is a fast, in-memory store that keeps copies of frequently accessed data to reduce database load and latency. Redis (Remote Dictionary Server) is the most widely used cache in industry.

Cache Strategies

Cache-Aside (Lazy Loading): App checks cache first. On miss, reads from DB and writes to cache. Most common pattern.
Read-Through: Cache itself fetches from DB on miss. App only talks to cache.
Write-Through: Write to cache AND DB simultaneously. Consistent but slower writes.
Write-Back (Write-Behind): Write to cache only, flush to DB asynchronously. Fast writes, risk of data loss.

Redis Data Structures

TypeUse case in system design
StringSimple key-value (session data, counters)
HashUser profile fields (hash per user ID)
ListMessage queues, activity feed (recent items)
Sorted SetLeaderboards (score → member, O(log n) rank)
SetUnique visitor tracking, tag membership
