⚡ Part A — Quiz

Question 1

A banking system must guarantee that money debited from one account is always credited to another (even on failure). Which property ensures this?

  • Atomicity (A in ACID)
  • Availability (A in CAP)
  • Eventual Consistency (BASE)
  • Partition Tolerance
Atomicity — a transaction either fully commits or fully rolls back. If the credit fails, the debit is reversed. This is ACID's "all-or-nothing" guarantee, critical for financial data.
Question 2

Your query: SELECT * FROM orders WHERE user_id = 42 AND created_at > '2024-01-01'. Which index would be MOST useful?

  • Single index on created_at
  • Single index on user_id
  • Composite index on (user_id, created_at)
  • No index needed — use a full table scan
Composite index on (user_id, created_at) — filters by user_id first (high cardinality, eliminates most rows), then further filters by date range using the second column. A single index on user_id helps but still needs to scan all orders for that user to filter by date.
Question 3

In the CAP theorem, during a network partition a CP system will:

  • Return stale data rather than an error
  • Return an error or reject the request rather than return inconsistent data
  • Route all traffic to the fastest available node
  • Automatically heal the partition before responding
Return an error — CP systems sacrifice Availability to maintain Consistency. If the system cannot guarantee the latest data, it refuses to respond rather than return stale data. Example: HBase, Zookeeper.
Question 4

Hash-based sharding with 4 shards. user_id=17 goes to which shard?

  • Shard 0
  • Shard 1
  • Shard 2
  • Shard 3
17 % 4 = 1 → Shard 1. Hash-based sharding distributes evenly by taking the modulo of the key against the number of shards.
Question 5

Primary-replica replication improves which type of traffic?

  • Read throughput (can distribute reads to replicas)
  • Write throughput (can write to any replica)
  • Both equally
  • Neither — it only improves availability
Read throughput — reads can go to any replica, distributing the load. Writes still go only to the primary (replicas are read-only). Replication also improves availability as a side benefit.

🗄️ Part B — Database Selection Workshop

For each system below, choose a database type and justify your choice. There may be more than one valid answer — justify your trade-offs.

System 1 — Social media posts

Users create posts with text, images, tags. 500M posts/day. Need to query "posts by user" and "posts by tag." Posts are never updated after creation. High read/write ratio 80/20.

Consider: Do you need joins between users and posts? Does schema flexibility matter? Would you use the same DB for user profiles vs. posts?

System 2 — E-commerce checkout

Order creation deducts inventory AND charges a credit card. Failed charges must roll back inventory. Moderate traffic (10,000 orders/hour). Order history must be queryable by date range.

Consider: Which ACID property is critical here? Would NoSQL work? What index would you add for the date-range query?

System 3 — Real-time leaderboard

A game tracks scores for 10M players. Every score update must be immediately reflected in the top-100 leaderboard. 100,000 score updates/sec. Leaderboard is read by 1M users/sec.

Consider: Would a traditional DB work? What Redis data structure is ideal? Would you use Redis as the primary store or a cache in front of a DB?

🤝 Part C — Peer Review Checklist

  • DB choice justified with a specific reason (not just "NoSQL is faster")?
  • Index specified by column name, not just "add an index"?
  • Replication lag acknowledged if using async replication?
  • Sharding strategy named (hash/range/directory) and shard key justified?
  • CAP trade-off stated: is this system CP or AP during a partition?

📝 Part D — Weekly Reflection

  1. Research: what is "consistent hashing" and how does it solve the resharding problem in hash-based sharding?
  2. Draw a diagram: a primary DB with 2 replicas, showing which nodes handle reads, which handles writes, and what happens if the primary fails.
  3. Given a 1TB database table growing at 100GB/month, estimate when you would need to shard. What would your shard key be if the table is user transactions?
