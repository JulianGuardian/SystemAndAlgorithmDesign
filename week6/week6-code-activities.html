⚡ Quick Quiz — Stacks & Queues

Question 1

Which problem type is a monotonic stack most suited for?

  • Finding the shortest path in a graph
  • Finding the next greater element for each item in an array
  • Sorting an array in O(n log n)
  • Checking if a binary tree is balanced
Next greater element — the monotonic stack is the canonical O(n) solution for "next/previous greater/smaller" problems. As you scan, elements that get popped have found their answer (the current element is greater than them).
Question 2

Why should you use collections.deque instead of a list for a queue?

  • deque supports more methods than list
  • deque uses less memory than list
  • list.pop(0) is O(n), deque.popleft() is O(1)
  • deque is thread-safe, list is not
O(1) popleft — removing from the front of a Python list requires shifting every remaining element, making it O(n). deque is implemented as a doubly-linked list at its ends, so both append and popleft are O(1). For BFS with large graphs, this difference is critical.
Question 3

What is the time complexity of BFS on a graph with V vertices and E edges?

  • O(V²)
  • O(V log V)
  • O(E log V)
  • O(V + E)
O(V + E) — BFS visits every vertex once (V) and traverses every edge once (E) to enqueue neighbors. Space is also O(V) for the visited set and queue. This applies equally to DFS.
Question 4

In the sliding window maximum (deque) solution, what invariant does the deque maintain?

  • Values at deque indices are in decreasing order; front is always the max
  • Values at deque indices are in increasing order; back is always the max
  • The deque always holds exactly k indices
  • Each index appears in the deque at most twice
Decreasing order, front = max — before adding index i, we pop from the back any index j where nums[j] < nums[i], because j can never be the window maximum while i is in the window (i is newer AND larger). The front holds the current window max.
Question 5

isValid("([)]") should return False. Which condition in the stack solution catches this?

  • The stack is not empty at the end
  • When processing ')' the top of stack is '[', which doesn't match
  • The string has an odd length
  • The stack overflows
Mismatch on pop — processing '(' pushes '(', '[' pushes '['. When we reach ')', we check stack top which is '[' — this doesn't match '(' (the expected match for ')'), so we return False immediately.

#155 · Min Stack

Medium

Design a stack that supports push, pop, top, and getMin() in O(1) time.

Stack Auxiliary Stack

Use two stacks: main stack and a min_stack that tracks the current minimum. When pushing x, push to main stack and push min(x, min_stack[-1]) to min_stack. getMin() returns min_stack[-1].

#739 · Daily Temperatures

Medium

Given an array of daily temperatures, return an array where each element is the number of days until a warmer temperature. Return 0 if no such day exists.

Monotonic Stack Array

Maintain a stack of indices (not temperatures). Push each index. When temperatures[i] > temperatures[stack[-1]], pop the stack and set result[popped_idx] = i - popped_idx.

#239 · Sliding Window Maximum

Hard

Given array nums and window size k, return the maximum of each window as it slides from left to right.

Monotonic Deque Sliding Window

Maintain a deque of indices (values decreasing). Before adding i: (1) remove front if out of window, (2) pop back while nums[back] < nums[i]. Append i. When i >= k-1, output nums[dq[0]].

#542 · 01 Matrix

Medium

Given a binary matrix, return the distance of the nearest 0 for each cell. BFS from all 0s simultaneously.

BFS Multi-source BFS Matrix

Initialize queue with ALL zero cells at distance 0. Mark non-zero cells as infinity. BFS expands outward from all zeros simultaneously. When a cell is first reached, its distance is set (BFS guarantees shortest). O(m*n) time and space.

🤝 Peer Review Checklist

  • Stack vs deque choice: Used list for stack (O(1) pop from right), deque for queue (O(1) popleft)?
  • Monotonic invariant maintained: Correct condition for when to pop (greater vs smaller)?
  • Window boundary check: In sliding window problems, removed out-of-window indices from deque front before appending result?
  • Complexity stated: O(n) time despite the while loop inside the for (amortized — each element pushed/popped once)?
  • Edge cases handled: Empty string for parentheses? k larger than array for sliding window?
  • BFS visited set: In graph BFS, marked nodes as visited when enqueued (not when dequeued) to avoid duplicates in queue?
