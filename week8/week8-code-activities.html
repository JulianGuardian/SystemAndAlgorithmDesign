⚡ Part A — Concept Quiz

Question 1

Python's heapq module implements which kind of heap by default?

  • Min-heap (root is the smallest element)
  • Max-heap (root is the largest element)
  • It adapts based on the data type
  • Neither — it requires explicit comparators
Min-heap. heapq.heappop() always returns the smallest element. To simulate a max-heap, negate values: push -x and negate the result on pop. This is a common Python interview trick.
Question 2

To find the k-th largest element in an array of n elements, you maintain a min-heap of size k. What is the time complexity?

  • O(n)
  • O(n log n)
  • O(n log k)
  • O(k log n)
O(n log k). Each of the n elements may trigger a heap push or replace, each costing O(log k) since the heap size stays bounded at k. When k ≪ n, this is much faster than sorting at O(n log n).
Question 3

In a heap stored as an array, what is the index of the right child of the node at index i?

  • 2i + 1
  • 2i + 2
  • i // 2 + 1
  • (i + 1) * 2
2i + 2. Left child = 2i + 1, right child = 2i + 2. Parent of node at index i = (i − 1) // 2. These formulas enable the heap to be stored as a flat array without pointer overhead.
Question 4

Merging k sorted lists with N total nodes using a heap costs O(N log k). Why log k and not log N?

  • The heap is rebuilt from scratch for each of the N nodes
  • Each push/pop operates on a heap of size N
  • The k lists are first sorted, adding a log N factor
  • The heap never exceeds size k — one entry per list — so heap operations cost log k
Heap size = k, not N. The heap holds exactly one node per list (the current front). At any point there are at most k nodes in the heap, so push/pop is O(log k). We do this N times total → O(N log k).
Question 5

When should you prefer heapq.nlargest(k, iterable) over sorting the entire array?

  • Always — nlargest is always faster
  • When k is much smaller than n — O(n log k) vs. O(n log n)
  • Only when the input is already partially sorted
  • Never — sorted() is always more readable
When k ≪ n. nlargest uses a heap internally and costs O(n log k). When k approaches n, full sort at O(n log n) becomes competitive (and simpler). For k = 1, use max() at O(n).

#215 · Kth Largest Element in an Array

Medium

Find the k-th largest element in an unsorted array. Note: it is the k-th largest in sorted order, not the k-th distinct.

Min-Heap size k O(n log k)

Build a min-heap of the first k elements. For each remaining element, if it's larger than the heap root, replace the root. At the end, the root is the k-th largest.

#347 · Top K Frequent Elements

Medium

Return the k most frequent elements. You may return the answer in any order. Your algorithm's time complexity must be better than O(n log n).

Counter Heap O(n log k)

Count frequencies with Counter. Use heapq.nlargest(k, count, key=count.get) — or build your own min-heap of size k keyed on frequency.

#23 · Merge K Sorted Lists

Hard

Merge k sorted linked lists into one sorted list. Return the merged list.

Min-Heap size k O(N log k) Tiebreaker index

Push (node.val, i, node) for each list head into a heap. Pop the minimum, advance that list, push the next node. Include index i to avoid comparing ListNode objects.

#973 · K Closest Points to Origin

Medium

Return the k closest points to the origin (0,0) in 2D space. Distance = √(x² + y²).

Max-Heap size k Negated distance

Use a max-heap of size k (negate the squared distance). When the heap exceeds k, pop the farthest. No need to take the square root — squared distance preserves ordering.

#1046 · Last Stone Weight

Easy

Stones: each turn smash the two heaviest. If equal, both destroyed; otherwise, remainder survives. Return the last stone weight (or 0).

Max-Heap Simulation

Push all stones negated into a min-heap (simulating max-heap). Each turn pop two, compute remainder, push back if nonzero.

🤝 Part D — Peer Review Checklist

  • Heap type correct: Is a min-heap used for k-th largest (not max-heap), and vice versa for k-th smallest?
  • Tiebreaker in merge: Does the solution include an index or counter to avoid comparing custom objects?
  • heapify vs. repeated push: Does the solution use heapify when converting a full list, rather than pushing one by one (O(n) vs O(n log n))?
  • Squared distance: Does K Closest Points avoid computing sqrt (unnecessary for comparisons)?
  • Complexity stated: Are both time O(n log k) and space O(k) identified for heap-based solutions?
  • Edge cases: Is k = 1 (use max/min), k = n (sort entire array), or empty input handled?
