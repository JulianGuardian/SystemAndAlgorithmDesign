⚡ Part A — Concept Quiz

Question 1

In-order traversal of a valid Binary Search Tree always produces output in which order?

  • Descending (largest first)
  • Ascending (smallest first)
  • Level order (breadth-first)
  • Random — depends on insertion order
Ascending. The BST invariant (left < root < right) means in-order traversal visits nodes in sorted order. This property is used to verify BSTs and to find the k-th smallest element in O(n).
Question 2

The LCA algorithm for a general binary tree uses which traversal order?

  • Pre-order (root → left → right)
  • In-order (left → root → right)
  • Post-order (left → right → root)
  • Level-order (BFS)
Post-order. We must gather information from both subtrees before deciding whether the current node is the LCA. Post-order processes children before the parent, enabling the "if both subtrees return non-null → this is the LCA" logic.
Question 3

What is the space complexity of maxDepth on a completely skewed (linked-list-like) binary tree with n nodes?

  • O(1)
  • O(log n)
  • O(n log n)
  • O(n)
O(n). The recursion stack depth equals the tree height. For a balanced tree that's O(log n), but a skewed tree (all nodes in one direction) has height n, so the call stack grows to O(n).
Question 4

Why is checking only the immediate children insufficient to validate a BST?

  • A descendant node can violate the BST property with an ancestor, not just its direct parent
  • In-order traversal is always faster for validation
  • Children cannot be compared without first sorting them
  • The root node has no parent to compare against
Descendants can violate ancestor constraints. For example, a right child of a left subtree must be less than the root — not just less than its direct parent. The min/max bounds approach tracks these inherited constraints as you recurse.
Question 5

In the iterative in-order stack algorithm, after popping a node, what do you do next?

  • Push the node's left child and stop
  • Push the node's right child and loop left again from it
  • Append the node's value to the result, then move current to the node's right child
  • Re-push the node and move to its left child
Visit, then go right. Popping means we've exhausted the left subtree. We record the value (visit), then set curr = node.right to start the process for the right subtree. The outer while loop then drives left as far as possible from there.

#104 · Maximum Depth of Binary Tree

Easy

Given the root of a binary tree, return its maximum depth (the number of nodes along the longest path from root to the farthest leaf node).

DFS Recursion O(n) time

Base case: if not root: return 0. Recurse on left and right, return 1 + max(left, right).

#235 · Lowest Common Ancestor of a BST

Medium

Given a BST and two nodes p and q, find their LCA. You can exploit the BST property for a cleaner O(h) solution.

BST O(h) time

If both p and q are less than root, go left. If both are greater, go right. Otherwise, root is the LCA.

#236 · Lowest Common Ancestor of a Binary Tree

Medium

Same problem but for a general binary tree — you cannot use BST ordering.

Post-order DFS O(n) time

If root is None, p, or q — return root. Recurse left and right. If both return non-null, root is the LCA. Otherwise, return whichever side is non-null.

#98 · Validate Binary Search Tree

Medium

Given the root of a binary tree, determine if it is a valid BST.

DFS Min/Max bounds

Use a helper check(node, lo, hi). Each node must satisfy lo < node.val < hi. Pass updated bounds when recursing: left gets hi=node.val, right gets lo=node.val.

✏️ Part C — Traversal Trace Exercise

Consider the binary search tree built by inserting values 4, 2, 7, 1, 3, 6, 9 in that order. The resulting tree:

Python#         4
#        / \
#       2   7
#      / \ / \
#     1  3 6  9

Manually trace each traversal without running code. Write the output sequence for:

  1. In-order: ______ ______ ______ ______ ______ ______ ______
  2. Pre-order: ______ ______ ______ ______ ______ ______ ______
  3. Post-order: ______ ______ ______ ______ ______ ______ ______
  4. LCA(1, 3) = ______  LCA(6, 9) = ______  LCA(1, 9) = ______
  5. maxDepth = ______  diameter = ______

Answers: In-order: 1 2 3 4 6 7 9 | Pre-order: 4 2 1 3 7 6 9 | Post-order: 1 3 2 6 9 7 4 | LCA(1,3)=2, LCA(6,9)=7, LCA(1,9)=4 | maxDepth=3, diameter=4

🤝 Part D — Peer Review Checklist

  • Base case correct: Does the recursion return the right value for None nodes (0 for depth, None for LCA)?
  • nonlocal used: In the diameter problem, is the max updated via nonlocal or a mutable container (list)?
  • BST bounds tightened correctly: Does left recursion pass hi=node.val and right recursion pass lo=node.val?
  • LCA early return: Does the code return early when the node IS p or q, rather than continuing to search unnecessarily?
  • Iterative in-order terminates: Does the while condition check both curr AND stack to handle the rightmost node?
  • Complexity stated: Are both time and space complexities identified, distinguishing balanced vs. skewed trees?
