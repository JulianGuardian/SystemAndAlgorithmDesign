⚡ Part A — Quiz

Question 1

A celebrity with 50 million followers posts a tweet. Which fan-out model is most problematic and why?

  • Fan-out on Read — too many DB reads at post time
  • Fan-out on Write — must write tweet ID to 50M Redis entries, taking minutes
  • Both are equally problematic for celebrities
  • Neither — Redis handles this transparently
Fan-out on Write. Writing to 50M Redis timeline caches is extremely slow and strains fan-out workers. Twitter's solution is the hybrid model: fan-out on write for regular users, pull for celebrities at read time.
Question 2

In WhatsApp, what does a double grey checkmark (✓✓) mean?

  • Message sent to WhatsApp's servers
  • Message delivered to the recipient's device
  • Message read by the recipient
  • Message encrypted successfully
Delivered to device. Single grey ✓ = server received it. Double grey ✓✓ = device received it (may be in background, not yet opened). Blue ✓✓ = read in the app. This three-state receipt system requires the recipient's device to send acknowledgments back.
Question 3

Why does WhatsApp use WebSockets instead of standard HTTP polling for message delivery?

  • WebSockets use less CPU
  • WebSockets support end-to-end encryption natively
  • WebSockets allow the server to push messages to clients without the client polling
  • HTTP polling is not supported on mobile devices
Server push. HTTP is request-response: the client must initiate every exchange. With WebSockets, a persistent bidirectional TCP connection is established, allowing the server to push a message the moment it arrives — critical for real-time chat.
Question 4

What Redis data structure is ideal for storing a user's pre-built newsfeed timeline?

  • Sorted Set (ZSET) — score = timestamp, enables chronological feed slicing
  • Hash Map — key = tweet ID, value = tweet content
  • Set — for fast membership testing of tweet IDs
  • String — serialize and store the entire feed as JSON
Sorted Set. ZADD user:feed {timestamp} {tweet_id} lets you fetch the latest N tweets with ZREVRANGE user:feed 0 N-1 in O(log n + N). The score (timestamp) provides chronological ordering and efficient range queries.
Question 5

In Twitter's hybrid fan-out model, what criterion typically triggers switching from fan-out on write to fan-out on read?

  • Number of daily tweets by the user
  • Geographic location of the user
  • Follower count exceeding a threshold (e.g., 10,000–50,000)
  • Whether the user is a verified account
Follower count threshold. Beyond a certain follower count, the write amplification of fan-out on write becomes too expensive. The threshold (~10K–50K followers) is tuned based on observed system load. Verified status alone is not the criterion — a newly verified account with few followers still uses push.

🖊️ Part B — Design Workshop: Instagram Newsfeed

In pairs, design the newsfeed system for an Instagram-like app with the following requirements:

Requirements

  • 500M registered users, 50M daily active users
  • Users can follow up to 2,000 accounts; some influencers have 5M+ followers
  • Feed shows latest 20 posts from followed accounts, in reverse-chronological order
  • Posts include image + caption; images are up to 5MB
  • Feed must load in <300ms for 99th percentile
  • Users post an average of 2 times per day

Questions to answer in your design

  1. Which fan-out model will you use for regular users? For influencers?
  2. What will you store in Redis vs. the persistent database?
  3. How do you serve images at scale? Which CDN strategy?
  4. How do you paginate the feed (infinite scroll)?
  5. What happens when a followed account deletes a post that is already in a follower's pre-built cache?

🖊️ Part C — Design Workshop: WhatsApp Read Receipts

Problem

Design the read receipt system for a messaging app with 2B users and 100B messages/day. When Alice sends a message to Bob, Alice sees: ✓ (sent), ✓✓ (delivered), 🔵✓✓ (read).

Guiding questions

  1. Where is the receipt state stored? (On the sender's device? On the server? Both?)
  2. How does the server know Bob's device has received the message vs. just pulled it from the queue?
  3. How does the "read" state propagate back to Alice if she is offline when Bob reads it?
  4. In a group of 200 members, how many receipt events fire when one person reads a message? How would you aggregate them?
  5. What happens if Bob turns off read receipts in settings? Where do you enforce that privacy preference?

🤝 Part D — Design Review Checklist

  • Fan-out model chosen and justified with specific reasoning (not just "it's faster")?
  • Hybrid threshold defined — what follower count triggers the switch, and why?
  • Cache invalidation addressed — what happens when a followed user deletes a post?
  • WebSocket vs. polling decision made explicit for real-time features?
  • Storage tiering explained — what lives in Redis, what in the persistent DB?
  • Single points of failure identified and redundancy proposed?

📝 Part E — Reflection

  1. Research: how does Instagram's algorithm rank posts in a feed (it's not purely chronological)? Which components of the architecture would change to support ranking?
  2. If WhatsApp servers cannot read messages due to E2EE, how does the spam/abuse detection system work? Research client-side scanning.
  3. Estimate the storage cost of Twitter's Redis timeline cache: assume 100M active users, each with a feed of 800 tweet IDs (each 8 bytes). How many GB of Redis RAM is needed?
